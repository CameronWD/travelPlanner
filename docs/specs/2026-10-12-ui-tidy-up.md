# Spec — UI tidy-up from the 2026-10-12 layout audit

**Status:** agreed in the 2026-10-12 session (grill), building on branch
`chore/hygiene-and-ui-cleanup-2026-10-12`. Target `main`.
**Source:** `docs/audits/2026-10-12-layout-audit.md` and
`docs/audits/2026-10-12-layout-findings.json` (every `LA-1xx` below; each
entry carries the reviewer's *what / where / suggestedFix*). The suggested
fixes are leads; the decisions here win.

## What this is, and is not

A **tidy-up**: overflow, clipping, sideways scroll, chrome covering content,
dark-theme leaks, and visual inconsistency between neighbouring pages, on
phones and desktops. It is **not** a redesign and does not migrate the
header-swap pages to the Playground kit. Nothing changes a page's anatomy;
where a layout has to change (header stacking, a sticky map) it is the
smallest change that removes the defect.

Decided in the session:

- Every **Broken** and **Ugly** finding is fixed on this branch without a
  per-item review. **Polish** findings are listed in §C for Cam to pick
  from; none is built unless picked.
- The three **rulings** in §B are built as recommended unless Cam says
  otherwise; they are flagged because they change a layout, not a style.
- Two reviewer findings were struck as capture artefacts and are not work
  (`LA-112` Share "Day by day" blank: reveal-on-scroll; `LA-103` Day page
  shifted: a real viewport sits exactly one page in). Two more are verified
  first and struck if the same (`LA-132`, `LA-135`, see W15 and W16).

## Branch rules

Same as every branch: never commit to, merge into, rebase onto or push
`main`; never deploy; never run `feedback:resolve`; subagents never run
`feedback:pull`; don't commit `next dev`'s CLAUDE.md block. No Feedback note
is attached to this work.

## Verification tiers

Per `CLAUDE.md`. In addition, a task that touches a route re-shoots it:

```
BASE_URL=http://localhost:3000 LAYOUT_AUDIT_OUT=/tmp/layout-audit/2026-10-12b \
LAYOUT_AUDIT_AUTH_STATE=/tmp/layout-auth.json \
```

and reads the new PNGs (a filtered run merges into the manifest). The dev

contrast audit (`npm run audit:contrast`) must end **PASS** once W3 and W17
are in; W17 adopts the Share and Money node-count baselines.

## A. Work items (Broken and Ugly), by root cause

### W1 · Page header stacks below `md` and wraps above it

`LA-101 LA-102 LA-104 LA-107 LA-108 LA-114 LA-116 LA-121 LA-124 LA-138 LA-145 LA-154`
(Money, Plan, Calendar, Wishlist, Trip Help, Compare, Checklists, Files,
Journal, Activity, every width up to 1024).

`components/ui/page-header.tsx` puts the title column and a `shrink-0` side
cluster (fork pill, share, bell, and the mobile `+`) on one row. With four
controls the title column collapses and `break-words` prints the h1 one
letter per line; at 768 the desktop actions spill past the viewport.

**Decision (ruling R1, built as recommended):**

- Below `md`: two rows. Row 1 is the `trailing` cluster (fork pill, share,
  bell) right-aligned, full width. Row 2 is the title column with the
  `mobileAction` (+) at its right, `items-start`. The title column is
  `min-w-0 flex-1` and the h1 drops `break-words` for normal wrapping
  (`[overflow-wrap:normal]`); a long trip name eyebrow may `truncate` with a
  `title`.
- From `md`: one row, `flex-wrap`; the side cluster may wrap under the title
  when it does not fit, `justify-end`. The title column keeps
  `min-w-[14rem]` so it never starves. The h1 never breaks inside a word.
- Pages that render their own header rather than `PageHeader` and show the
  same squeeze (Trip Help `app/(app)/trips/[tripId]/help`, Compare,
  Calendar) are moved onto `PageHeader` only if they already pass `title`
  and actions the same way; otherwise they get the identical two-row rule
  in place. The implementer lists which it was.
- Tests: `page-header.test.tsx` asserts the two-row structure below `md`
  (data-slots in order) and that the h1 has no break-anywhere class.

### W2 · Page foot clears the Feedback button

`LA-115 LA-118 LA-122 LA-142 LA-153` (Summary, Money, Checklists, Settings,
Account; also Polish `LA-174 LA-180`).

The fixed Feedback launcher (`feedback-launcher.tsx:566`) sits
`bottom-[calc(var(--tp-tab-bar-h)+1.5rem+safe-area)]` on phones; the two
layouts pad the page bottom only for the tab bar
(`app/(app)/layout.tsx:209`, `trips/[tripId]/layout.tsx:218`).

**Decision:** both layouts add the launcher's footprint to their bottom
padding: `+ 2.75rem + 1.5rem` below `md` (44px button + gap), `+ 2.75rem +
1rem` from `md`. One shared CSS variable `--tp-fab-clearance` defined next
to `--tp-tab-bar-h` so the launcher and the layouts agree. Print unchanged.
Test: a layout test asserts the padding class references the variable.

### W3 · Share page owns its ink

`LA-113` (Share, dark; 66 contrast failures).

`app/share/[token]/page.tsx:602` marks the root `data-theme="light"` +
`light` but sets no text colour, so with `.dark` on `<html>` the body's cream
`--foreground` inherits onto white cards.

**Decision:** the root (and `not-found.tsx`'s) gets `text-foreground` and
`[color-scheme:light]`; any share component that sets a colour from the
`dark:` variant is checked (the spec of 2026-10-01 §A already switches the
variant off inside the root, so this should be none). Verify with
`npm run audit:contrast`: zero failures on `/share/{token}` in dark.

### W4 · Share hero title wraps at spaces

`LA-134` (Share, 360 and 1024–1440).

**Decision:** the hero h1 keeps `text-balance` and drops whatever allows a
break inside a word; font size steps down one notch (`clamp`) in the band
where the hero shares a row with the route card. "EU Christmas 2026" never
splits inside "Christmas" or "2026" at any audited width.

### W5 · Plan header and rows at 1024–1280

`LA-111 LA-130` (Plan desktop).

**Decision:** in `stop-row-header` the date/stepper cluster stacks under the
title below `xl`; the chips wrap before the h2 truncates; the title wins
over the stepper. In day rows the title span is `min-w-0 truncate` with a
`title`, and the Booked chip + price are `shrink-0` so they never paint over
the title.

### W6 · Plan phone sheets and pills

`LA-109 LA-110` (Add a stop sheet 360/390; past-trip transport pills 375).

**Decision:** find why the "Where to?" input in the Add-a-stop sheet paints
as a 60px black bar at 360/390 (`form.flex > div.overflow-hidden >
input.h-[60px]` overlapping the "HOW LONG" label) and fix it so the field

sheet at phone width and asserts the input is visible and not overlapped.
Transport pills in the mobile list get `min-w-0 max-w-full` with the route

### W8 · Dialog header clears the Close button

`LA-131` (every dialog; seen on Adjust dates at 1440).

`dialog.tsx:315` already pads the sticky header `pr-16`, yet the title runs
under the `absolute right-4` Close at `sm:right-5`. **Decision:** find why

asserts the title's right edge is left of the Close button's left edge.
