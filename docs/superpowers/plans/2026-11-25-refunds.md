# Refunds on a Cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A paid Cost can carry one Refund (expected or received); every money total uses the net once it is received; deleting a paid-for thing asks what happened to the money.

**Architecture:** Two nullable columns on `Cost` (`refundMinor`, `refundedAt`), added in a migration-only commit. One zod-free module, `lib/money/refund.ts`, owns the state, the net arithmetic and the rule messages; totals change in exactly one conversion point (`convertCostToHome`) plus the two functions that read raw rows (`buildSpendSoFar`, `mergeToPay`). Deletion keeps ADR 0039's conversion and gains an optional answer per Cost.

**Tech Stack:** Next.js 16, React 19, Prisma 7 (Postgres), zod 4, Tailwind 4, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-25-refunds.md`

## Review Focus

1. Any existing write to a Cost that does not know about Refunds (the inline cost row in the Transport, Accommodation and Item forms, `markCostPaid`, a currency change, a Fork) must neither wipe a Refund nor leave one larger than the paid amount. Tests in Tasks 3 and 5.
2. An expected Refund changes no total anywhere. Tests in Task 4.
3. A fully refunded Cost contributes exactly zero to every total and never a negative. Tests in Tasks 2 and 4.
4. The Budget's sum invariant (by Chapter + ungrouped + between legs + Other costs = grand total, for cost and paid) holds with refunded Costs in each bucket. Test in Task 4.
5. Deleting with "Refunded" for less than the paid amount leaves an Other cost worth exactly the difference; an answer naming a Cost that is not the owner's, or an amount over the paid amount, is refused and nothing is deleted. Tests in Task 5.

### Task 2: The Refund rules module

**Files:** create `lib/money/refund.ts`, `lib/money/refund.test.ts`.

**Interfaces — Produces:**

```ts
type When = Date | string | null | undefined;
export interface RefundBearing { costMinor: number; paidMinor: number | null; paidAt: When; refundMinor: number | null | undefined; refundedAt: When }
export type RefundState = "none" | "expected" | "received";
export function refundState(c: Pick<RefundBearing, "refundMinor" | "refundedAt">): RefundState;
/** The Refund amount that counts in totals: 0 unless the Cost is paid and the Refund is received. */
export function receivedRefundMinor(c: Pick<RefundBearing, "paidAt" | "refundMinor" | "refundedAt">): number;
export function netCostMinor(c: RefundBearing): number;
/** null when the Cost has no paid amount; otherwise never below 0. */
export function netPaidMinor(c: RefundBearing): number | null;
export const REFUND_MESSAGES: { tooMuch: string; notPaid: string; unpayBlocked: string };
/** The rule a Cost breaks, or null. Checks: a Refund needs a paid Cost; 1 ≤ refundMinor ≤ paidMinor; refundedAt needs refundMinor. */
export function refundProblem(c: Pick<RefundBearing, "paidMinor" | "paidAt" | "refundMinor" | "refundedAt">): string | null;
```

`REFUND_MESSAGES`: `tooMuch` "A refund can't be more than what was paid.", `notPaid` "Mark it paid before recording a refund.", `unpayBlocked` "Remove the refund before marking this unpaid." (match the repo's apostrophe convention for visible copy).

- [ ] **Step 1:** CONTEXT.md, Money section, add after **Paid**:

```markdown
**Refund**:
Money that came back on a **Paid** **Cost**: an amount in the Cost's own currency, never more than was paid, and one of two states. **Expected** means it has been promised and changes nothing yet; **Received** means it has arrived, on a date the Traveller gives. A received Refund makes the thing cheaper: every total (**Trip cost**, **Spend so far**, the **Budget**'s roll-ups) counts the Cost at its cost amount less the Refund and its paid amount less the Refund, never below zero. The Cost still shows one number, the net, with the Refund named beside it. A Cost has at most one Refund, and cannot be un-marked paid while it has one. Deleting a Transport, Accommodation or Item that was paid for asks what happened to the money; the **Other cost** it leaves carries the answer.
_Avoid_: Reimbursement, credit, chargeback; "refundable" (that is whether an **Item**'s ticket can be refunded, a property of the ticket, not money that came back)
```
